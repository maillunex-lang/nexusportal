# NEXUS PORTAL 1.0 · утверждённая спецификация
Дата: 2026-11-16. Статус: утверждено владельцем в диалоге, реализация поэтапная.

## Цель
Универсальная self-hosted PWA-система управления проектами: игры, Android-приложения, сайты, серверы, прочий софт. Без платных ИИ API, без постоянно работающей LLM. Внешние ChatGPT/Claude/Codex получают копируемые обучающие промпты, инструкции и задачи. Портал выполняет детерминированную автоматизацию.

## Архитектура
Backend Python 3.12+; SQLite WAL; HTTP API; PWA интерфейс с безопасной авторизацией. GitHub REST API + HMAC SHA256 webhook. Фоновая идемпотентная очередь событий; при потере webhook резервная сверка. Отдельные роли: директор (внешний ИИ), исполнитель (внешний ИИ), автоматический оркестратор (код). Не изображать наличие собственной нейросети.

## Мастер
Создание/подключение проекта -> анализ дерева репозитория -> предпросмотр diff -> подтверждение -> создание только отсутствующих файлов через GitHub API -> стартовый промпт -> GDD и решения -> work_plan.json -> задачи. Обучающие файлы: README, docs/AI_RULES.md, docs/DIRECTOR_HANDOVER.md, docs/PORTAL_PROTOCOL.md, docs/work_plan.json, docs/WORK_PLAN.md, docs/gdd/DECISIONS_APPROVED.md, tools/work_plan.py, CI workflow. Проектные шаблоны: universal, godot, android, web, backend.

## Задачи
Источник истины: docs/work_plan.json; зависимости DAG без циклов; статусы planned/ready/in_progress/blocked/done; каждая задача имеет id, цель, GDD, file scope, depends_on, done_when, branch, PR, CI. Промпты формируются детерминированно. Только директор меняет общие файлы.

## GitHub и CI
Не доверять одному флагу success. Проверять актуальный head SHA, mergeable, required checks (явно заданные и непустые), branch protection, scope, принадлежность PR задаче, отсутствие kill switch. Merge идемпотентный, с expected SHA; только после подтверждённого merged менять done. Ошибки дают готовый repair prompt. PR из недоверенных форков не запускает деплой. Действия от webhook верифицировать и дедуплицировать по delivery id.

## SSH и релизы
SSH-исполнитель на одном VPS; полномочия владельца настраиваются отдельно для каждого проекта. Запускать только доверенные versioned deploy recipes, не команды из PR. Предварительные копии и рабочий rollback. Dev/prod раздельно; после успешного релизного CI автоматически публиковать именно подписанный/валидированный артефакт для актуального SHA. Проверка checksum, версия, атомарная замена, сохранение двух rollback-релизов, уведомление. Приватные ключи остаются на VPS. Не трогать другие сервисы.

## Память
SQLite: проекты, события, решения, задачи, журнал аудита, публикации, контекст. GitHub GDD и work_plan являются каноническими артефактами. Контекст для ИИ генерируется из актуального снимка, без секретов. Разделение по проектам.

## Интерфейс
Русский, Forest Glass 2.0, 360px+, Android safe-area, PWA, темы light/dark, доступность. Страницы: Главная, Проекты, Мастер, Дорожная карта, Задачи/промпты, GitHub/CI, Релизы/APK, Память, Уведомления, Настройки. Мониторинг ресурсов не нужен.

## Безопасность
Авторизация, HttpOnly Secure SameSite cookie, CSRF, CSP, rate limiting, журнал аудита, секреты только в файлах 0600 на VPS. Для GitHub write используется общий fine-grained token с минимальными правами; не отдавать браузеру. Резервные копии SQLite с проверкой восстановления. Kill switch на проект и глобально.

## Критерии приёмки 1.0
Создание проекта не перезаписывает существующие файлы; копируемый стартовый промпт; roadmap DAG; PR зелёный -> merge -> done; красный -> repair prompt; deploy/release с откатом; память и handover; Telegram/MAX; безопасный доступ; зелёный обязательный CI. Никаких обязательных скриншотов или ручной повторной QA.
