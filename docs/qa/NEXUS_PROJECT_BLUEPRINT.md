## Реализовано

- JSON Schema Draft 2020-12, schema_version 1.0, строгие обязательные поля и инертные дополнительные метаданные. Эталонный project_blueprint.example.json и три проекта с разной структурой: Godot economic MMO, морской кооператив, Kotlin Android.
- Загрузка до 1 MiB, schema/path/branch/DAG-валидация, запрет дублирующихся ключей и чрезмерной вложенности. Ни одно значение JSON не исполняется.
- Версии документа с SHA-256 и append-only защитой. Отдельные runtime-таблицы задач, PR/тестов, аудита и снимков выданных промптов. Аддитивная идемпотентная миграция SQLite WAL.
- Детерминированная очередь и объяснения блокировок. Только accepted разблокирует зависимости. Приоритет, ID, пересечения зон, одинаковые рабочие ветки и активные задачи учитываются внутри транзакции выдачи.
- Пустые зоны допускаются. Неизвестные зоны резервируют эксклюзивную последовательную работу. После изучения репозитория директор может уточнить пустую зону активной задачи; новый контекст сохраняется отдельным снимком без изменения старого.
- Промпт архитектора сохраняется неизменным. Служебный контекст включает документы, зависимости, зоны, критерии, проверки, ветку/PR и отчёт. SHA поступает только от живого GitHub branch_sha. Типовые опасные инструкции блокируются; смысловую проверку подтверждает директор.
- Кнопка копирования атомарно выдаёт задачу и сохраняет промпт. Повторное копирование возвращает сохранённый снимок. Предусмотрено ручное копирование при недоступном clipboard.
- Статусы todo/ready/in_progress/pr_open/tests_passed/accepted/blocked/failed/cancelled; приёмка требует роли owner и решения с причиной. Успешный CI/merge не принимает задачу.
- Безопасное обновление: добавленные/изменённые/удалённые задачи, поля до/после, изменения зависимостей, исторический diff утверждённых версий, подтверждения активных изменений и сброса принятия у изменённых задач и зависимых потомков. Устаревшие drafts отклоняются. История удалённых/возвращённых задач не теряется.
- Русский интерфейс: Blueprint, дорожная карта, доступные задачи, карточка задачи, версии. Светлая/тёмная темы, 360 px+, клавиатурный фокус, labels, aria-live, CSS safe overflow.
- Session auth, CSRF, роли owner/executor/viewer, HttpOnly/SameSite cookie, scrypt, login limiter, CSP и безопасный textContent. Изолированный локальный запуск и адаптер существующей авторизации full-v1.
- Read-only GitHub: PR, head SHA, checks/statuses, changed files с пагинацией, merged; защита от смены SHA во время проверки, чужой ветки/репозитория/форка. При отсутствии подключения сохраняется ручной режим. Merge/deploy API не вызываются.

## Использование

Полная инструкция и API: docs/BLUEPRINT.md. Локальный запуск: установить backend/blueprint/requirements.txt, интерактивно выполнить python -m backend.blueprint.app --init-owner, затем python -m backend.blueprint.app --local-http. Открыть http://127.0.0.1:8765/blueprint. JSON → предпросмотр → утверждение → проверка задания → копирование/выдача → PR и тесты → приёмка.

## Допущения и ограничения

1. Основой служит свежий main, где runtime пока отсутствует. Поэтому модуль имеет собственный запуск и точку встраивания в FastAPI. Добавление ссылки /blueprint в общую навигацию и вызова attach выполняется при согласованной интеграции full-v1. Чужую реализацию не копируем и не сливаем в текущую ветку.
2. Все изменения Blueprint утверждает директор. Это задание имеет приоритет над прежними документами об автоматических merge/done: для Blueprint нет автоматической приёмки или слияния.
3. Без AI API невозможно надёжно понять любое противоречие естественного языка. Используются консервативные правила и обязательная документированная проверка директором. Инертные дополнительные метаданные не становятся неявными исполняемыми ограничениями.
4. Непересечение файловых префиксов — консервативная оценка, не доказательство отсутствия архитектурных конфликтов. Общие контракты архитектор обязан отразить в зонах/зависимостях. Неоднозначные wildcard-пересечения сериализуются.
5. GitHub-свидетельства не являются автоматической сертификацией required checks или соответствия изменённых файлов смысловым требованиям. PR, CI и зоны оцениваются директором перед accepted. Checks/statuses используют существующие методы клиента; автоматизации принятия нет.
6. Самостоятельный auth рассчитан на один worker: сессии и limiter в памяти, после перезапуска потребуется вход. Для основной установки предусмотрен существующий auth адаптер. Не создавались реальные аккаунты, не запрашивались секреты.
7. Интерфейс проверен эмуляцией ширины Android в Chromium, не на физическом Android-устройстве. Релиз на VPS и интеграция общей навигации вне этого задания; рабочие базы, сайты, сервисы, чужие ветки и main не изменялись.
8. SQLite-триггеры защищают от обычных изменений через приложение, а не от владельца файлов БД, который может сам заменить схему. Встроенного удаления истории нет; резервное копирование предоставляется инфраструктурой хоста.

PR оставлен открытым. Слияние требует отдельного разрешения владельца.
