# Протокол NEXUS PORTAL

## Роли
- **Владелец** — утверждает ключевые решения, включает автоматизацию, разрешает продакшен.
- **ИИ-директор** (внешний ChatGPT/Claude) — ведёт GDD и `docs/work_plan.json`, выдаёт задачи.
- **Исполнители** (внешние ChatGPT/Claude/Codex) — выполняют задачи в отдельных ветках.
- **Портал** — детерминированная автоматика без ИИ.

## Жизненный цикл задачи
`planned` → `ready` (все зависимости `done`) → `in_progress` (открыт PR с веткой задачи или `[ID]` в названии)
→ `blocked` (упал обязательный CI; готов промпт исправления) → `done` (только после подтверждённого слияния).

## Автоматическое слияние
Условия: автослияние разрешено проекту; нет глобального и проектного аварийного выключателя; PR в основную
ветку, не из форка, не черновик, привязан к задаче; обязательные проверки заданы и все успешны на актуальном
head SHA; конфликтов нет. Слияние выполняется с проверкой SHA, затем открываются следующие задачи.

## Релизы
Артефакт релизного workflow: `release.json`
(`{"version":"1.2.3","version_code":10203,"channel":"release","sha":"<SHA>","file":"app-1.2.3.apk"}`),
`SHA256SUMS`, файл сборки. Примеры — `templates/`.

## Дорожная карта
`python3 tools/work_plan.py check | next | lanes | prompt <ID> | render --write`

## NEXUS Smart Context (экономия токенов)
- `docs/PROJECT_INDEX.md` — компактная карта; `docs/context/modules.json` — машинный индекс: документы, модули,
  каталоги, контракты, тесты, зависимости модулей (без циклов).
- GDD разделён на тематические файлы `docs/gdd/*.md`; `docs/GDD.md` — оглавление.
- `python3 tools/context_pack.py pack <ID> --level brief|standard|extended` — пакет задачи: цель, нужные документы
  (ссылки и короткие выдержки, без копирования GDD), модули и их зависимости, контракты, публичные интерфейсы,
  разрешённые файлы, тесты, критерии. Критические правила и межмодульные контракты присутствуют на всех уровнях.
- Порядок чтения исполнителя: индекс → документы и файлы задачи → прочее только при необходимости.
- `check [--strict]` — неизвестные документы/модули, циклы, устаревшие ссылки на отсутствующие файлы;
  `index --write` — пересобрать PROJECT_INDEX.md после изменения структуры.

## NEXUS Project Blueprint
После утверждения GDD и дорожной карты ИИ-архитектор формирует единый JSON `nexus-blueprint/1`
(промпт: docs/blueprint/ARCHITECT_PROMPT.md, стандарт: docs/blueprint/README.md). Владелец импортирует и
утверждает его в портале («Blueprint»), после чего «Что делать сейчас» выдаёт готовые задания одним нажатием.
ID задач стабильны между версиями — по ним сохраняются прогресс и история.
