# NEXUS Project Blueprint · стандарт `nexus-blueprint/1`

Blueprint — единый JSON-документ, который **ИИ-архитектор** формирует после утверждения GDD и дорожной карты.
В нём все этапы, потоки работ, задачи в правильной последовательности, зависимости, приоритеты, критерии
приёмки и подробные промпты для исполнителей. Подходит для любых жанров, движков и структур репозиториев.

| Файл | Назначение |
|---|---|
| `blueprint.schema.json` | JSON Schema (draft 2020-12) — официальный формат |
| `template.json` | пустой шаблон для заполнения |
| `ARCHITECT_PROMPT.md` | универсальный промпт для ИИ-архитектора (ChatGPT, Claude и др.) |
| `examples/game-platformer.json` | пример: 2D-платформер на Godot (8 задач, 3 этапа, 5 потоков) |
| `examples/android-habits.json` | пример: Android-приложение на Kotlin/Compose |
| `examples/web-catalog.json` | пример: сайт + API с контрактом OpenAPI |

## Принципы

1. **Портал не придумывает задачи.** Всё проектирует архитектор. Портал проверяет документ, вычисляет
   очерёдность и безопасный параллелизм, выдаёт задания и отслеживает PR/CI.
2. **Структура репозитория не навязывается.** Пути в `scope_hints` — только подсказки. Исполнитель сам изучает
   репозиторий и определяет нужные файлы.
3. **Состояние не хранится в документе.** Статусы ведёт портал (`planned → ready → in_progress → blocked → done`);
   `done` — только после зелёного обязательного CI и слияния PR.
4. **ID задач стабильны.** При обновлении blueprint по ID сохраняются история, PR и прогресс.
5. **Без платных ИИ API.** Промпты копируются внешним исполнителям.

## Поля

### Корень
| Поле | Обяз. | Описание |
|---|---|---|
| `format` | да | всегда `nexus-blueprint/1` |
| `blueprint_version` | да | версия документа (`1.0`, `1.1`, `2.0.1`); увеличивайте при каждом изменении |
| `generated_at`, `generated_by` | нет | дата и автор |
| `project` | да | `name`, `summary` обязательны; `kind`, `genre`, `platforms`, `tech_stack`, `repository`, `default_branch` — по желанию |
| `sources` | да | `gdd` — список ссылок на утверждённый GDD; `roadmap`, `decisions`; `approved: true` после утверждения владельцем |
| `conventions` | нет | правила для всех задач (ниже) |
| `phases` | да | этапы **в порядке выполнения**: `id`, `title`, `goal`, `exit_criteria` |
| `workstreams` | нет | параллельные линии: `id`, `title`, `description` |
| `tasks` | да | задачи (ниже) |

### `conventions`
| Поле | По умолчанию | Описание |
|---|---|---|
| `branch_pattern` | `task/{id}` | ветка задачи; `{id}` заменяется ID в нижнем регистре |
| `pr_title_pattern` | `[{id}] {title}` | название PR — по нему портал связывает PR с задачей |
| `max_parallel` | 3 | сколько задач одновременно в работе |
| `parallel_within_workstream` | `false` | можно ли параллельно выполнять задачи одного потока |
| `required_checks` | — | обязательные проверки CI; добавляются к настройкам проекта при утверждении |
| `definition_of_done` | — | общие критерии готовности |
| `global_rules` | — | правила, добавляемые в каждое задание |

### Задача
| Поле | Обяз. | Описание |
|---|---|---|
| `id` | да | латиница, цифры, `_.-`, до 48 символов; стабилен между версиями |
| `title`, `goal` | да | название и результат одной фразой |
| `phase` | да | ID этапа |
| `workstream` | нет | ID потока работ |
| `priority` | нет | `P0` (блокирует релиз) … `P3`; по умолчанию `P2` |
| `type` | нет | feature, bugfix, refactor, infra, test, docs, content, art, audio, research, release |
| `estimate` | нет | XS, S, M, L, XL |
| `executor_hint` | нет | claude, chatgpt, codex, generic, any — рекомендуемый исполнитель |
| `depends_on` | нет | задачи, которые должны быть **слиты** до начала этой |
| `conflicts_with` | нет | задачи, которые нельзя выполнять одновременно |
| `resources` | нет | логические области (`save-format`, `db-schema`, `api-contract`); общий ресурс = нельзя параллельно |
| `gdd_refs` | рекоменд. | ссылки на разделы GDD вместо копирования текста |
| `context` | нет | короткий контекст |
| `deliverables` | нет | ожидаемые результаты |
| `acceptance_criteria` | да | проверяемые критерии приёмки |
| `verification` | рекоменд. | чем CI проверит результат |
| `scope_hints` | нет | подсказки по путям (относительные, без `..`) |
| `out_of_scope`, `risks` | нет | что не делать; известные риски |
| `prompt` | да | подробное задание исполнителю, ≥ 200 символов |

## Как портал определяет, что делать сейчас

1. **Порядок** — топологическая сортировка зависимостей; среди доступных: раньше этап → выше приоритет →
   длиннее критический путь (сколько задач ждут эту) → порядок в документе.
2. **Готовые** — задачи, все `depends_on` которых слиты (`done`).
3. **Безопасный параллелизм** — готовая задача выдаётся, если она не конфликтует ни с задачами в работе,
   ни с уже выбранными: нет общего `resources`, нет пары в `conflicts_with`, не тот же `workstream`
   (если `parallel_within_workstream: false`), не пересекаются `scope_hints`; и не превышен `max_parallel`.
4. Остальные готовые попадают в «Отложены» с причиной; неготовые — в «Ждут» со списком зависимостей.
5. Заблокированные упавшим CI задачи — в «Требуют внимания» вместе с промптом исправления.

## Жизненный цикл в портале

1. **Импорт** — «Blueprint» → вставить JSON, загрузить файл или «Загрузить из GitHub» (`docs/blueprint.json`).
   Поддерживается также формат плана Adaptive Project Engine (PR #2) — он конвертируется автоматически.
2. **Проверка** — ошибки блокируют импорт; предупреждения показываются. Повторный импорт того же документа не создаёт новую версию.
3. **Черновик** — новая версия с номером; видно отличия от утверждённой: добавлено, удалено, изменено (по полям).
4. **Утверждение** владельцем — предыдущая версия получает статус `superseded`; задачи синхронизируются
   с дорожной картой портала. Статусы, PR и история сохраняются по ID. Удаление задач в работе требует подтверждения.
5. **Выполнение** — «Что делать сейчас» → «Копировать для Claude / ChatGPT / Codex» → исполнитель открывает PR
   (ветка задачи или `[ID]` в названии) → портал следит за CI → сливает → открывает следующие задачи.
6. **История** — каждое событие задачи (добавлена, изменена, PR открыт/обновлён, CI упал, слита, удалена, задание скопировано).

## Командная строка (без портала)

```bash
python3 backend/blueprint/core.py validate docs/blueprint.json
python3 backend/blueprint/core.py order docs/blueprint.json
python3 backend/blueprint/core.py next docs/blueprint.json --done G01,G02 --active G05
python3 backend/blueprint/core.py prompt docs/blueprint.json G03 --executor claude
```

`core.py` использует только стандартную библиотеку Python и может быть скопирован в любой проект.
